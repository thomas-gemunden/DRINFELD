# D_8 vs {D_8, Q_8} detection at m ≥ 3 — does D_8 alone suffice?

**Date:** 2026-05-17
**Issue:** #215 (R-1 follow-up to #193 / PR #205)
**Status:** complete — verdict **KEEP Q_8**

## Section 1: The question

R-1 (issue #193, PR #205) raised the following hypothesis in the
detecting-family literature note (`docs/superpowers/research/2026-05-17-detecting-family-literature.md`,
"Surprise findings" item, lines 335–337):

> D_8 alone may actually suffice mathematically. Both D_8 and Q_8 carry
> Z/8 in H^4(−; Z) generated by their central Z/4 quotient; the
> restriction E_+(m) → D_8 should catch A(4) (Z/8 at m=2, Z/4 at m ≥ 3).
> The D-VAN-FIX #151 empirical failure may have been Aut(G)-equivariance
> or implementation-specific rather than a fundamental mathematical gap.

If this hypothesis held, we could simplify the detecting family from
{E, D_8, Q_8} back to {E, D_8}, dropping one branch each from D-VAN and
K-4a. The verdict below resolves that hypothesis.

## Section 2: Theoretical analysis

### Section 2.1: The "central Z/4 quotient" claim is mathematically wrong for D_8

The R-1 hypothesis hinges on the assertion that **both D_8 and Q_8 carry
Z/8 in H^4(−; Z)** generated by a "central Z/4 quotient". This is wrong
for D_8. The correct statement is:

| Group | Centre | Maximal cyclic in H^4(−; Z) | Reason |
|---|---|---|---|
| D_8 | Z/2 | **Z/4** | abelianisation (Z/2)², central Z/2 (cyclic in the LHS spectral sequence has order 4 from the Z/4 normal subgroup) |
| Q_8 | Z/2 | **Z/8** | periodicity of period 4: H^4(Q_8; Z) ≅ Z/|Q_8| = Z/8 (cf. AM04 §IV.2 Theorem 2.9 + Lemma 2.10) |

Concretely from the codebase's HAP computation (`SetupCohomology3` on
`SmallGroup(8, 3)` and `SmallGroup(8, 4)`):

- **H^3(D_8; U(1)) ≅ H^4(D_8; Z) ≅ Z/2 × Z/2 × Z/4** — `torsion_D8 = [2, 2, 4]`.
- **H^3(Q_8; U(1)) ≅ H^4(Q_8; Z) ≅ Z/8** — `torsion_Q8 = [8]`.

The asymmetry has a clean structural reason:

- **D_8 has abelianisation (Z/2)²** and centre Z/2. The cyclic Z/4 subgroup
  ⟨r⟩ ≤ D_8 is normal but NOT central (since `srs = r^(-1)`). The
  Lyndon–Hochschild–Serre spectral sequence for the central extension
  Z/2 ↪ D_8 ↠ (Z/2)² gives the well-known F_2-ring
  F_2[x, y, w]/(xy), and the integral cohomology has maximum cyclic
  factor 4 (from the Z/4 contribution of the normal-but-not-central
  cyclic) in degree 4.
- **Q_8 has every order-2 element central** (just z = a² = b² = (ab)²).
  All three maximal subgroups ⟨a⟩, ⟨b⟩, ⟨ab⟩ are cyclic of order 4 and
  each contains the central Z/2. The Tate cohomology is 4-periodic
  (AM04 §IV.2 Theorem 2.9), so H^4(Q_8; Z) ≅ Ĥ^0(Q_8; Z) ≅ Z/|Q_8| = Z/8.

So "central Z/4 quotient" in R-1's quote was loose language conflating
"cyclic subgroup of order 4" (D_8 has one but it's not central) with
"central subgroup of order 4" (D_8 doesn't have one — its centre is only
Z/2). Q_8 is special precisely because its centre IS the unique order-2
subgroup of all three of its Z/4's.

### Section 2.2: Restriction H^3(E_+(m); U(1)) → H^3(D_8; U(1)) and the A(4) summand

By Harada–Kono 1987 Theorem 1.1, H^4(E_+(m); Z) ≅ A(4) ⊕ V where:

- **m = 2** (h(Q) = 2): A(4) = Z/8 (since n(4) = 2 ≥ h(Q), so
  a(4, Q) = h(Q) + 1 = 3).
- **m ≥ 3** (h(Q) ≥ 3): A(4) = Z/4 (since n(4) = 2 ≤ h(Q) − 1, so
  a(4, Q) = n(4) = 2).

V is an elementary abelian 2-group, captured by Quillen 1971 Theorem 5.10
via restriction to maximal elementary abelian subgroups.

The question is whether res: A(4) → H^4(D_8; Z) is **faithful** (injective
when restricted to the A(4) summand) at m ≥ 3.

**Mathematically**, A(4) ≅ Z/4 has order 4, and H^4(D_8; Z) ≅ Z/2 × Z/2 × Z/4
contains a Z/4 sub. So *in principle* there exists an injective Z/4 → Z/4.
The question is whether the **actual** restriction map lands as an
injection on that Z/4 sub, or only as the multiplication-by-2 map
Z/4 → Z/4 (which has kernel = the order-2 sub-element).

From the Harada–Kono transfer-restriction formula (their Lemma 3.2 and
the structural argument in §3): for any Q-isotropic preimage W^- = π^(-1)(W)
inside V^- = E_+(m), the transfer-restriction composition

```
t ∘ r : H^*(V^-; Z) → H^*(V^-; Z)
```

equals multiplication by 2^(h(Q)) where h(Q) is the codimension of W in V.

For a D_8 section of E_+(m): D_8 itself sits inside E_+(m) as the
preimage of a Q-isotropic line in V (= E_+(m)/Z(E_+(m))) — that is, a
1-dimensional W with W^- ≅ D_8. So h(Q|W) = m − 1 (the W is 1-dim, V is
2m-dim, so codim = 2m − 1; but here "h" in HK convention counts something
slightly different — actually h(Q|W^-) for the quadratic form *restricted*
to W^- is 1, as W^- is itself an h=1 extraspecial = D_8). The relevant
transfer-restriction count is 2^h on the *D_8 cohomology* side, which is
2^1 = 2.

But more directly: the **image** of res: A(4) → H^4(D_8; Z) restricted
to the Z/4 sub of H^4(D_8) is multiplication by some integer. Empirically
(see Section 3) this integer is **2 mod 4** at m = 3 — i.e., the A(4)
generator maps to the order-2 element of D_8's Z/4 sub. **Its image is
the Z/2 sub of Z/4, not all of Z/4.**

So restriction to D_8 catches `A(4)_gen` (since 2 ≠ 0 in Z/4) but **misses
2 · A(4)_gen** (since 2 · 2 = 4 ≡ 0 in Z/4). The order-2 element of A(4)
maps to the zero class in H^4(D_8; Z).

This is a **genuine cohomological gap**, not an implementation bug.

### Section 2.3: Why Q_8 catches it where D_8 fails

Q_8 is NOT a Q-isotropic preimage in E_+(m). The Harada–Kono /
Adem–Milgram structural decomposition (AM04 §IV.2 Remark 2.13) writes

```
E_+(m) = D_8 ∗ D_8 ∗ ... ∗ D_8     (m copies, real type)
       ≅ Q_8 ∗ Q_8 ∗ D_8 ∗ ... ∗ D_8  (using D_8 ∗ D_8 ≅ Q_8 ∗ Q_8)
```

so Q_8 appears as a section of E_+(m) for m ≥ 2 via the rebracketing.
But the Q_8 section is NOT the preimage of a Q-isotropic subspace; it is
the preimage of a Q-**anisotropic** 2-dimensional subspace (one on which
Q is non-degenerate). The transfer-restriction formula `t ∘ r = 2^h`
applies only to Q-isotropic preimages, so it imposes **no constraint** on
Q_8 detection.

Q_8 has H^4(Q_8; Z) ≅ Z/8, a single cyclic group of order 8 with no
elementary abelian 2-summand to "absorb" the order-4 element. The
restriction res: A(4) → H^4(Q_8; Z) is a Z/4 → Z/8 map, and empirically
(see Section 3) it lands on an ODD element of Z/8 (specifically 6 mod 8
in our pinned Q_8 section at m = 3). The composition A(4) → Z/8 is
injective in this case (1·6 = 6, 2·6 = 12 = 4, 3·6 = 18 = 2, all non-zero
in Z/8), so Q_8 catches every non-zero class of A(4).

This explains the structural asymmetry: **D_8 is constrained by the
transfer-restriction ceiling at the order-2 sub-element of A(4); Q_8
is not.**

## Section 3: Empirical experiment

### Section 3.1: Experimental setup

I re-ran the D-VAN-FIX (#151) failing case at m = 3 with two
configurations:

1. **Configuration (a)** — full {EA, D_8, Q_8} via current
   `ResIsTrivialOnDetectingFamily(3, ω)`.
2. **Configuration (b)** — {EA, D_8} only, via a local `CheckEDOnly`
   wrapper that mirrors `ResIsTrivialOnDetectingFamily` but elides the
   Q_8 check (`all_EA_zero AND all_D8_zero`).

For the test ω I used the cyclic A(4) generator `e_g = [0, ..., 0, c]`
where the non-zero entry sits at `exp_index_m3 = 35` (the position with
torsion 4 in `torsion_G = [(Z/2)^34, Z/4]`), for c ∈ {0, 1, 2, 3} sweeping
all four classes of the Z/4 summand.

### Section 3.2: Configuration (a) — full {EA, D_8, Q_8}

The current code passes its existing test (in
`tests/test_detecting_family_vanish.g` line 274–286):

```
c | true non-zero? | trivial verdict
0 | false (is_zero) | true   (correct)
1 | true            | false  (correct)
2 | true (ord-2 of A(4)) | false  (correct — Q_8 catches it)
3 | true            | false  (correct)
```

Pinned restriction-matrix values for the cyclic generator:

- `res_D8[35] = [1, 0, 2]` in torsion `[2, 2, 4]`
- `res_Q8[35] = [6]` in torsion `[8]`

### Section 3.3: Configuration (b) — {EA, D_8} only

Re-running with Q_8 elided:

```
c | true non-zero? | {E,D_8} verdict
0 | false (is_zero) | true   (correct)
1 | true            | false  (correct)
2 | true (ord-2 of A(4)) | TRUE   (WRONG — false positive)
3 | true            | false  (correct)
```

**At c = 2, {E, D_8}-only reports trivial = TRUE, but the class is
non-zero in H^3.** This is the original D-VAN-FIX #151 failure mode
reproduced exactly.

Detail of the failure:
- `2 · e_g` projects to res_D8 as `2 · [1, 0, 2] = [2 mod 2, 0, 4 mod 4] = [0, 0, 0]`.
- All EAs have torsion 2 only, so doubling kills any class entirely (this
  is generic for 2-torsion — EAs cannot distinguish c=0 from c=2 in any case).
- Hence `{E, D_8}` sees zero everywhere and reports `trivial = true`.
- Meanwhile Q_8 sees `2 · [6] = [12 mod 8] = [4]` which is non-zero,
  correctly catching the discrepancy.

### Section 3.4: Exhaustive check across all D_8 conjugacy classes

To rule out the section-choice hypothesis ("maybe a different D_8 conj
class would catch it"), I enumerated **all 280 conjugacy classes of D_8
subgroups** of E_+(3) (= `Filtered(ConjugacyClassesSubgroups(G), IdGroup =
[8, 3])`) and computed their restriction rows on the A(4) generator.

**Result**: across all 280 D_8 conj classes, the third coordinate of
res_D8[35] takes values in **{0, 2}** ⊂ Z/4 (never odd). The six distinct
row patterns and their counts are:

```
row=[0, 0, 2] (torsion [2,2,4])  count=106
row=[0, 1, 0] (torsion [2,2,4])  count=11
row=[0, 1, 2] (torsion [2,2,4])  count=58
row=[1, 0, 2] (torsion [2,2,4])  count=77
row=[1, 1, 0] (torsion [2,2,4])  count=2
row=[1, 1, 2] (torsion [2,2,4])  count=26
                            total: 280
```

**Doubling any row gives `[0, 0, 0]`** — there is no D_8 conj class for
which the doubled row is non-zero:

```
Distinct D_8 rows on A(4) generator: 6
Distinct D_8 doubled rows: 1   (= [0, 0, 0])
Does ANY D_8 conj class detect 2·A(4)_gen? FALSE
```

So the failure is **uniform across the D_8 conjugacy structure**, not a
choice-of-section artefact. The structural reason is clear: H^4(D_8; Z)
has maximum cyclic factor Z/4, and the image of A(4) (also Z/4) in this
factor is always **multiplication by an even integer** — hence
2·A(4)_gen lies in the kernel.

### Section 3.5: Also fails at m = 2 for the order-2 element of Z/8

At m = 2, A(4) of E_+(2) is Z/8 (h = 2, n(k) ≥ h ⇒ a(4, Q) = h + 1 = 3).
The element `4 · e_g` is the **order-2 element** of Z/8 — a non-zero
class. Re-running the same diagnostic at m = 2:

- `res_D8[exp_idx] = [0, 0, 1]` in torsion `[2, 2, 4]`
- `res_Q8[exp_idx] = [1]` in torsion `[8]`

| c | true non-zero? | {E,D_8} verdict | Full verdict |
|---|---|---|---|
| 0 | false (zero) | true (correct) | true (correct) |
| 1 | true (ord 8) | false (correct) | false (correct) |
| 2 | true (ord 4) | false (correct, D_8 has [0,0,2]) | false (correct) |
| 4 | true (ord 2) | **TRUE (WRONG)**, D_8 has [0,0,0] | false (correct, Q_8 has [4]) |

The codebase's existing m = 2 test (`Task 2.5: Gate 1B`) tests only
`c = 1` (`e_z8`) and `c = 2` (`e_z8_half`), both of which D_8 catches.
It does NOT test `c = 4`. **D_8 alone also fails at m = 2 — just on a
different class (order-2 of Z/8 instead of order-2 of Z/4).**

This contradicts the previous note's claim that "D_8 alone is sufficient
at m = 2" (literature note, line 337). It was sufficient only on the
specific Gate 1B test, not in general.

## Section 4: Diagnostic — code bug or genuine cohomological gap?

### Section 4.1: Code is correct

The restriction matrix `res_D8` is computed by `RestrictionMatrixViaHAP`
in `detecting_family_restriction.g` (lines 116–190). The code applies
the standard `EquivariantChainMap` + `GroupCohomologyFunctor`
construction — the same machinery used in `H3MatrixOfAutomorphism`
(`brw_h3_action.g`), which has independent regression tests against
H^3-actions on H^3(G; U(1)).

The post-fix rescale strategy (Lcm-of-exponents, `L = lcm(exp_G, exp_H)`)
is mathematically correct for both `exp_H | exp_G` (D_8 case, m = 2:
`L = 8, rescale_G = 1, rescale_H = 4`) and `exp_G | exp_H` (Q_8 case,
m = 3: `L = 8, rescale_G = 2, rescale_H = 1`). This is the fix that
landed in the Q_8 extension (#156).

The output value `res_D8[35] = [1, 0, 2]` is reproducible and the
column-3 image `{0, 2}` over the full coordinate sweep is uniform across
all 280 D_8 conj classes. **The empirical observation is robust.**

### Section 4.2: The gap is genuine

The image of the restriction map H^3(E_+(3); U(1)) → H^3(D_8; U(1))
restricted to the Z/4 column of D_8 is `{0, 2}` ⊂ Z/4. The rank of this
restriction map over Z/4 (i.e., the dimension of the image as a Z/4
module) is **1** (= Z/2 ⊂ Z/4), not 2 (= all of Z/4).

This matches the structural prediction: A(4) ≅ Z/4 maps into Z/4 by
multiplication by 2, which has kernel the order-2 sub-element. No
finer-resolution section of D_8 type exists — D_8's own H^4 only has Z/4
to play with, and the restriction lands on the order-2 sub.

### Section 4.3: Aut(G)-equivariance

R-1's hypothesis also raised "Aut(G)-equivariance" as a possible cause.
This is not the issue here: the test cocycle `c · e_g` is by construction
a basis vector in `UCT.hombasis` coordinates and is **not** averaged
across Aut(G). The Aut(G)-orbit of `c · e_g` might be different (it
could mix into other classes), but the **per-class** detection question
is what we ask: is the restriction map H^3(G) → ⊕H^3(H_i) **injective**?
The Aut(G)-quotient sits downstream of injectivity; if res is not
injective on a single class, no Aut(G)-averaging will fix it.

To confirm: the empirical failure is on the bare basis vector, not on an
Aut-averaged class. So the Aut(G)-equivariance hypothesis does not
apply.

## Section 5: Verdict

**Verdict: KEEP Q_8 in the detecting family.** The R-1 hypothesis is
refuted.

### Reasoning

1. **D_8 alone is structurally insufficient**, not just at m ≥ 3 but
   also at m = 2 (for the order-2 element of A(4) = Z/8).
2. The failure mode is **uniform** across all 280 D_8 conjugacy class
   representatives at m = 3 — no D_8 section choice rescues it.
3. The failure is a **genuine cohomological gap**: H^4(D_8; Z) does not
   contain Z/8, only Z/4 (contrary to the R-1 quote). The cyclic A(4)
   summand of H^4(E_+(m); Z) maps to D_8's Z/4 by multiplication by 2,
   killing the order-2 sub-element on doubling.
4. The fix is **mathematically necessary, not redundant**: Q_8 has
   H^4(Q_8; Z) ≅ Z/8 (a property of Q_8 alone among 2-groups of order 8),
   so its restriction map can faithfully detect every order in A(4).

### Caveat on what changes

This verdict closes the question raised by R-1's "surprise finding" item
about whether `Q_8` could be dropped. The conclusion is **NO** — `Q_8`
is genuinely necessary at both m = 2 (for the order-2 element of Z/8)
and m ≥ 3 (for the order-2 element of Z/4).

The previous literature note (`docs/superpowers/research/2026-05-17-detecting-family-literature.md`)
lines 324–325 ("D_8 is in the family for redundancy / convention") and
line 337 ("D_8 alone is sufficient at m = 2") **should be revised** to
reflect this finding. The corrected statement is:

- D_8 catches the **F_2 part** of H^3(E_+(m); U(1)) — i.e., classes
  whose A(4) component is zero or whose A(4) component reduces to 0 mod
  the order-2 sub. Together with the elementary abelians it covers most
  of the F_2 detection.
- D_8 also catches the **order-4 component** of A(4) at m = 2 (where
  A(4) = Z/8 and D_8's Z/4 catches the Z/8 → Z/4 ↠ Z/4 quotient), but
  **misses the order-2 sub-element** at all m.
- Q_8 catches **every order-2 sub-element** of A(4) (via its Z/8 which
  doesn't quotient onto its order-2 sub).

So D_8 and Q_8 are **complementary**, not redundant: D_8 contributes
some F_2-side coverage and partial Z/4-coverage; Q_8 contributes the
order-2-of-A(4) detection that D_8 cannot. Both are needed for a sound
*triviality* test (`trivial=true` is reliable).

Actually a stronger statement is also true: **{EA, Q_8} alone might
suffice** (D_8 may be redundant given Q_8). This is the opposite of
R-1's hypothesis, and it would simplify the family in the other
direction. The empirical D_8 rows (`[1, 0, 2]` and variants on the
A(4) gen) suggest D_8 only adds detection power on the F_2 components,
which Quillen 1971 + EAs already cover. **However, this is out of scope
for #215** (which only asked about dropping Q_8); investigating whether
D_8 could be dropped is a *separate* follow-up.

## Appendix: Reproducibility

The empirical experiments in Section 3 were run via throwaway diagnostic
GAP scripts. None modify any committed code. They `Read`
`detecting_family_vanish.g` and then call `BuildRestrictionMatrices`
plus a local `CheckEDOnly` wrapper that elides the Q_8 check.

The minimal reproducer (m = 3 case, demonstrates D_8-alone failure on
2·A(4)_gen):

```gap
# Run from extraspecial_orbifolds/scripts/.
Read("detecting_family_vanish.g");

# Local helper: {E, D_8}-only check (ignores Q_8).
If_ := function(c, a, b) if c then return a; else return b; fi; end;;
CheckEDOnly := function(m, omega_vec)
    local rec_m, hom_omega, res_EA_vec_list, i,
          torsion_EA_i, res_EA_i, vec_int, vec_modH,
          res_D8_vec_int, res_D8_vec,
          all_EA_zero, trivial;
    rec_m := BuildRestrictionMatrices(m, "hap");
    hom_omega := NormaliseOmegaToHomBasis(rec_m, omega_vec);
    res_EA_vec_list := [];
    for i in [1..Length(rec_m.res_EA_list)] do
        torsion_EA_i := rec_m.torsion_EA_list[i];
        res_EA_i := rec_m.res_EA_list[i];
        vec_int := List([1..Length(torsion_EA_i)], j ->
            Sum([1..Length(hom_omega)], k ->
                hom_omega[k] * res_EA_i[k][j]));
        vec_modH := List([1..Length(vec_int)], j ->
            vec_int[j] mod torsion_EA_i[j]);
        Add(res_EA_vec_list, vec_modH);
    od;
    res_D8_vec_int := List([1..Length(rec_m.torsion_D8)], j ->
        Sum([1..Length(hom_omega)], k ->
            hom_omega[k] * rec_m.res_D8[k][j]));
    res_D8_vec := List([1..Length(res_D8_vec_int)], j ->
        res_D8_vec_int[j] mod rec_m.torsion_D8[j]);
    all_EA_zero := ForAll(res_EA_vec_list, v -> ForAll(v, x -> x = 0));
    trivial := all_EA_zero and ForAll(res_D8_vec, x -> x = 0);
    return trivial;
end;;

# 2 · A(4)_gen at m = 3 (the failing case).
rec_m3 := BuildRestrictionMatrices(3, "hap");;
exp_idx := Position(rec_m3.torsion_G, 4);;     # = 35
omega   := List([1..35], j -> If_(j = exp_idx, 2, 0));;
Print("{E, D_8}-only verdict on 2·A(4)_gen: ",
      CheckEDOnly(3, omega), " (WRONG — should be false)\n");
Print("Full {E, D_8, Q_8} verdict on 2·A(4)_gen: ",
      ResIsTrivialOnDetectingFamily(3, omega).trivial,
      " (correct — false, Q_8 catches it)\n");
```

Expected output:

```
{E, D_8}-only verdict on 2·A(4)_gen: true (WRONG — should be false)
Full {E, D_8, Q_8} verdict on 2·A(4)_gen: false (correct — false, Q_8 catches it)
```

The 280-D_8-class scan, m = 2 sweep, and rank-over-Z/4 analysis follow
the same pattern; full diagnostic scripts available from the issue
author on request (they were run in `/tmp/` during the investigation).

The numerical outputs (e.g., `res_D8[35] = [1, 0, 2]`, the 280-row
scan, the `{0, 2}` column-3 image) are reproducible across HAP runs
because the `EPlusGroup(m) = ExtraspecialGroup(2^{2m+1}, "+")` GAP
constructor is deterministic and `BuildRestrictionMatrices` caches per
`(m, source)`.
